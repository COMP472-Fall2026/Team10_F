## 1. Overview

We classify two Kaggle datasets of pre-extracted feature vectors:

| Dataset   | Train rows | Test rows | Features | Classes |
|-----------|-----------:|----------:|---------:|--------:|
| image     | 20,000     | 5,000     | 500      | 50      |
| sentiment | 12,000     | 5,000     | 768      | 3 (negative / neutral / positive) |

Models compared on both datasets:

- **k-Nearest Neighbors**, implemented from scratch with NumPy
- **Decision Tree** (Gini impurity), implemented from scratch with NumPy
- **Random Forest** (bagging + random feature subsets), implemented from scratch on top of our Decision Tree
- **Neural Network (MLP)**, implemented with PyTorch
- **k-Means clustering** (unsupervised experiment), implemented from scratch with NumPy

No machine-learning library (scikit-learn, etc.) is used: NumPy for the models, pandas only to read/write CSV files,
matplotlib for the figures, PyTorch only for the neural network.

All model choices (hyperparameters, preprocessing) are made on a **validation set** (stratified 80/20 split of the
training data), never on the Kaggle test set.

### `src/` — reusable code

| File | Purpose |
|------|---------|
| `src/data.py` | `load_dataset(name)`: reads `dataset/<name>_train.csv` and `dataset/<name>_test.csv`, returns `X_train, y_train, X_test, ids_test` as NumPy arrays (`float32` features). |
| `src/split.py` | `stratified_split(y)`: 80/20 train/validation split that keeps the class proportions; same seed = same split. |
| `src/metrics.py` | `accuracy`, `confusion_matrix`, `per_class_accuracy`. |
| `src/preprocessing.py` | `fit_standardizer` / `standardize`: z-score scaling, with mean and std computed on the training part only. |
| `src/models/knn.py` | k-NN: squared Euclidean distances, neighbor search, majority vote and distance-weighted vote, sweep over `k`. |
| `src/models/decision_tree.py` | Decision Tree: Gini impurity, best split search over candidate thresholds, recursive tree building, prediction. |
| `src/models/random_forest.py` | Random Forest: bootstrap samples, random feature subsets at each split (`n_features`), parallel tree building, majority vote, out-of-bag accuracy. |
| `src/models/neural_network.py` | MLP (PyTorch): `Linear + ReLU + Dropout` hidden layers, training loop (Adam, cross-entropy, mini-batches), evaluation; `fit` keeps the weights of the epoch with the best validation accuracy, `train_final` retrains on the full training set for a fixed number of epochs. |
| `src/models/kmeans.py` | k-Means: random initial centroids, assign each point to its closest centroid, move centroids to the mean of their points until no point changes cluster; cluster × class table and purity to compare the clusters with the labels. |

## 4. Data pre-processing

There is **no separate pre-processing step to run**: the features are already extracted by the Kaggle organizers,
and every script does the same short pipeline itself when it starts:

1. **Load** — `load_dataset(name)` reads the CSV files and keeps the `feature_*` columns as a `float32` matrix.
2. **Split** — `stratified_split(y_train)` keeps 80 % of each class for training and 20 % for validation
   (seed 42, so every script uses exactly the same split).
3. **Scale (depends on the model)** — mean and std are always computed on the training part only, to avoid
   data leakage.
   - k-NN: `run_knn.py` compares raw features with z-score standardized features. Raw features gave the better
     validation accuracy on both datasets, so k-NN uses **raw features**.
   - Decision Tree / Random Forest: raw features (a split threshold does not depend on the scale).
   - MLP (`scale_features` in `run_nn.py`): sentiment is **standardized** (z-score); image is **multiplied by
     √500**: its rows are L2-normalized (norm ≈ 1), so the raw values are around 1/√500; the same constant for
     every value brings them back around 1 without changing the shape of the data. It gave a better validation
     accuracy than standardization (see `figures/nn_image.png`).
   - k-Means: `run_kmeans.py` reports both raw and standardized features.

To check this pipeline on your machine:

```bash
python -m tests.check_data
python -m tests.check_split
python -m tests.check_pipeline
```

## 5. Train and evaluate

Each script trains on the 80 % training part and reports accuracy on the 20 % validation part.

```bash
# k-NN: accuracy for every k, raw vs standardized, simple vs weighted vote
python -m experiments.run_knn

# Decision Tree: train / validation accuracy for every max_depth (slow on image)
python -m experiments.run_tree

# Random Forest: number of trees, max_depth, n_features (a few minutes, uses all CPU cores but one)
python -m experiments.run_forest              # both datasets
python -m experiments.run_forest sentiment    # only one dataset

# Figures of the hyperparameter curves (k-NN and Decision Tree)
python -m experiments.plot_hyperparams

# Error analysis of the chosen models (per-class accuracy, confusions, confusion matrix figures)
python -m experiments.analyze_errors

# Neural network: learning rate, regularization, network size, scaling (a few minutes on CPU)
python -m experiments.run_nn

# 4x2 table: the 4 chosen models on both datasets (~5 min, see below)
python -m experiments.compare_models
```

```bash
# k-Means (unsupervised): clusters vs true labels, raw vs standardized features (~20 s)
python -m experiments.run_kmeans
```

### Chosen hyperparameters (validation set)

| Model | image | sentiment |
|-------|-------|-----------|
| k-NN | `k = 1`, weighted vote, raw features | `k = 61`, weighted vote, raw features |
| Decision Tree | `max_depth = 40` | `max_depth = 5` |
| Random Forest | 300 trees, `max_depth = None`, `n_features = "sqrt"` | 100 trees, `max_depth = None`, `n_features = "sqrt"` |
| MLP | hidden `[4096]`, dropout 0.6, `lr = 1e-3`, `weight_decay = 1e-3`, up to 60 epochs, features × √500 | hidden `[256]`, no dropout, `lr = 1e-4`, `weight_decay = 1e-2`, up to 30 epochs, standardized features |

The MLP is always trained with Adam, cross-entropy loss and mini-batches of 128; the weights of the epoch with the
best validation accuracy are kept.

## 6. Apply the model (Kaggle submission)

```bash
python -m make_submission
```

For each dataset, `make_submission.py`:

1. measures the validation accuracy of the chosen k-NN (`KNN_SETTINGS`) and of the chosen MLP (`NN_SETTINGS`)
   on the shared 80/20 split;
2. keeps the better of the two;
3. retrains it on the **full** training set (train + validation) — for the MLP, for the number of epochs that
   gave the best validation accuracy — and predicts the 5,000 test rows.

It then checks the format against `dataset/sample_submission.csv` (columns, ids, label ranges) and writes
`submission.csv` (`id,label`) at the root, printing the expected score (mean of the two validation accuracies).
This file is not tracked by git.

Current result (about 1 min 20 s on CPU):

| Dataset | k-NN (val) | MLP (val) | Kept |
|---------|-----------:|----------:|------|
| image | 0.5192 | 0.4355 | **k-NN** (`k = 1`, weighted) |
| sentiment | 0.5892 | 0.6796 | **MLP** (retrained for 9 epochs) |

Expected score ≈ **0.5994** (mean of the two validation accuracies).

## 8. Reproducibility

- `seeds.py` sets `SEED = 42` for `random`, NumPy and PyTorch; the split, the Random Forest, k-Means and the MLP
  (`torch.manual_seed(SEED)` before each training: initial weights, mini-batch order, dropout) use this seed.
- Same seed + same data = same split, same models, same validation numbers.
- Generated files (`figures/`, `results/`, `submission.csv`) can all be recreated with the commands above.
